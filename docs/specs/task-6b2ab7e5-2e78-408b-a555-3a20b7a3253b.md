# 功能規格：解決 php artisan migrate 時出現 "relation \"expenses\" already exists" 錯誤

## 問述
在執行 `php artisan migrate` 時，系統嘗試重複建立 `expenses` 資料表，導致 `SQLSTATE[42P07]: Duplicate table` 錯誤。這通常發生在：
- 之前已手動建立過該表（例如透過直接 SQL 或先前的遷移未正確回滾）；
- 遷移檔案缺少防止重複建立的機制（未使用 `ifNotExists` 或 `hasTable` 檢查）。

## 目標
使 `expenses` 資料表的遷移具備冪等性，無論資料表是否已存在，都能安全執行遷移而不拋出例外。

## 解決方案
1. **更新遷移檔案**：將 `Schema::create` 替換為 Laravel 提供的 `Schema::createIfNotExists`（Laravel 8.2+）或手動以 `Schema::hasTable` 進行條件檢查。
2. **保持外鍵約束**：`user_id` 仍使用 `foreignId` 指向 `users.id`（bigint），並確保 `users` 表先於 `expenses` 建立（遷移時間戳順序正確）。
3. **不新增不存在的外鍵**：僅參考已存在的 `users` 表，遵守專案約束。

## 實施步驟
- 後端工程師修改 `database/migrations/xxxx_xx_xx_xxxx_create_expenses_table.php`。
- 修改後執行 `php artisan migrate:fresh` 或直接 `php artisan migrate` 驗證不再發生重複表錯誤。
- 前端無需變更，但 QA 需確認功能不受影響。

## 預期結果
- 執行 `php artisan migrate` 時，不再出現 `Duplicate table` 錯誤。
- `expenses` 表結構符合原定 schema（`id`, `user_id`, `amount`, `description`, `expense_date`, `created_at`, `updated_at`）。
- 外鍵約束正常：`expenses.user_id` 參考 `users.id`，刪除使用者時依據設定的 `onDelete` 行為執行。
- 後續的遷移和 seeding 能正常進行。
